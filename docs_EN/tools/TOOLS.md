# BK Evolution — tools/ Inventory

> Last updated: 2026-09-11 (verified against code)
>
> This document inventories all 35 Python scripts and subdirectories under `tools/`, grouped by purpose.
> Scripts marked **historical** were one-off migration/fix scripts; most contain hardcoded absolute paths (`C:\Users\akxls\...`) and **cannot be reused directly** — they are kept as historical records only.
> Scripts marked ⚠️ contain hardcoded paths; edit the paths before running.

---

## 1. Translation workflow chain (active)

The standard workflow is in [`../i18n/I18N_ROADMAP.md`](../i18n/I18N_ROADMAP.md) §4. Core chain:

```
translate --empty → export_empty_to_xlsx → (manual/MT Excel)
→ import_translated_empty → audit_placeholders → i18n_lint / verify_i18n
```

| Script | One-line description |
|------|-----------|
| `export_empty_to_xlsx.py` | Exports all empty translations (empty entries in `strings.rpy` + empty dialogue blocks) to Excel for manual translation |
| `export_empty_to_xlsx_v2.py` | Same as above, but only scans empty `new ""` string blocks in all `.rpy` files under `game/tl/chinese_simplified/` (does not export dialogue) |
| `import_translated_empty.py` | Imports empty translations back from Excel (default `temp/translations/to_translate_empty.xlsx`), writing into Ren'Py translation files |
| `import_translated_remaining_v3.py` | Imports translations from `to_translate_remaining_v3.xlsx` (strings / common / dialogue sheets) |
| `auto_fill_nonenglish_empty.py` | Auto-fills empty entries whose source is already non-English (e.g. hardcoded Chinese) with `new = old`, skipping manual translation |
| `export_remaining_english.py` | Exports all empty translations still in English (strings + string blocks per file + dialogue blocks) |
| `batch_translate_empty.py` | Batch machine-translates empty entries in `strings.rpy` with `deep_translator` (requires network; small batches + progress output) |
| `audit_placeholders.py` | Audits placeholder consistency between Chinese translations and originals (`%s/%d` and `[var]` interpolations), outputs mismatch Excel |
| `import_placeholder_fixes.py` | Imports the placeholder-fixed Excel back into the corresponding `.rpy` translation files (rows whose placeholders still mismatch are skipped) |
| `audit_json_i18n.py` | Scans `_i18n` strings in `game/core/data/**/*.json` using the same rules as `json_i18n.rpy`, checks for missing entries in `strings.rpy`, and outputs Excel |
| `import_json_i18n.py` | Imports JSON `_i18n` missing texts into `strings.rpy` (triple-quoted multi-line, deduped by source text, escaping) |
| `import_json_i18n_translations.py` | Imports the missing-entry Excel translations generated by `audit_json_i18n.py` back into `strings.rpy` (reuses v3 import logic) |
| `count_untranslated.py` | Quick count of `new ""` empty entries in `strings.rpy` and each translation file |
| `check_json_i18n.py` | Simple check: builds a source-text index of `strings.rpy` and verifies JSON `_i18n` texts are collected |
| `verify_i18n.py` | i18n regression verification: runs `translate --count`, `Ren'Py lint`, and `i18n_lint.py` in sequence, summarizing PASS/FAIL (paths derived automatically from the script location) |
| `i18n_lint.py` | Static audit of `game/core/**/*.rpy`: bare strings, `+` concatenation, unwrapped `%` formatting, etc. (current baseline: 17 false positives on developer-facing text, see [`../i18n/I18N_ROADMAP.md`](../i18n/I18N_ROADMAP.md)) |
| `debug_lint.py` | Debug helper for i18n_lint: verifies the `is_translatable()` decision logic |
| `remove_orphan_translations.py` | Removes orphan translation blocks from translation files by `file.rpy:translate_id` argument ⚠️ hardcoded TL_DIR |
| `audit_tl_structure.py` | Audits the correspondence between the translation directory structure and the source directory (orphan translation files / source files missing translations) |
| `scan_menu_options.py` | Scans `game/core/**/*.rpy` for non-literal `menu:` options (variable options need `__()` wrapping) ⚠️ hardcoded ROOT |
| `wrap_yes_no_strings.py` | Batch-wraps bare string literals in `call_screen("yes_no", ...)` with `__()` ⚠️ hardcoded GAME_DIR |
| `wrap_notify.py` | Batch-wraps bare strings in `renpy.notify("...")` with `__()` |
| `batch_wrap_economy.py` | Batch-wraps player-visible `%` formatted strings in `economy.rpy` (known variables such as ttip/change_log/budget_ttip) |
| `fix_screens_job_tooltip.py` | One-off fix converting the concatenated customer-preference tooltip strings in `screens.rpy` to `__()`-wrapped segments ⚠️ hardcoded paths |

## 5. bk_editor editor suite (active)

| Entry | Description |
|------|------|
| `bk_editor.py` | Main entry of the editor suite (`python tools/bk_editor.py`), tkinter GUI |
| `bk_editor/` | The suite itself: Girl Pack Editor / Scenario Editor / Dev Console + `shared/` shared library |

Three editors: **Girl Pack Editor** (for mod authors: picture tagging, `_BK.ini`, Trait/Perk, pack validation), **Scenario Editor** (for story authors: StoryEvent CRUD, scenario management), **Dev Console** (for core developers: JSON editing of achievements/difficulty/NG+/Meta).

Detailed documentation: [`bk_editor/README.md`](../../tools/bk_editor/README.md) (architecture and data file mapping), [`bk_editor/AGENTS.md`](../../tools/bk_editor/AGENTS.md) (AI agent coding conventions). The correspondence with `game/core/data/` is also in [`../modding/CUSTOM_DIRECTORIES.md`](../modding/CUSTOM_DIRECTORIES.md).

## Usage advice

- **Daily translation completion**: use only the active scripts in Section 1, following the `I18N_ROADMAP.md` §4 workflow.
- **Adding/modifying the Mod API**: run `python tools/verify_mod_api.py` for regression.
- **Changing JSON data structures**: follow the "modifying JSON data structures" checklist in `tools/bk_editor/AGENTS.md` (DataLoader + DataExporter + Schema + editor forms + fallback).
- **Historical scripts**: do not run directly (hardcoded paths are stale); if similar functionality is needed, copy and edit the paths.
